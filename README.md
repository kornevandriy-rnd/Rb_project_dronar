# Польотний тест камери (Raspberry Pi на дроні)

Pi на автономному живленні, до польотника не під'єднаний. Камера по USB
(ESP32 UART JSON @921600 + UVC-відео). Протягом 10:00 кожні 30–35 с перемикає
камеру за сценарієм і пише відео.

    python3 flight_test.py --plan            # сценарій (19 кроків, 10:00)
    python3 flight_test.py                   # запуск зараз (камера під'єднана)
    python3 flight_test.py --auto            # чекати камеру → старт (автостарт)
    python3 flight_test.py --fake --speed 20 # симуляція без камери

Автостарт на Pi: `crontab -l` → `@reboot ... flight_test.py --auto --delay 5`
(прибрати: `crontab -e`). Після кожного ввімкнення тест іде один раз, лише коли
з'явиться камера.

Результат: автозапуск (`--auto`) → `~/Вильоти-фіксації/rb_auto_test_РРРР-ММ-ДД_ГГ-ХХ-СС/`
(чекає NTP до 90 с; без часу — суфікс `_час-не-синхр`); ручні й `--fake` запуски →
`~/test-video/test_РРРР-ММ-ДД_ГГ-ХХ-СС/`. Усередині теки:
- `raw.mp4` — чисте відео; `annotated.mp4` — з інфо-смугою (крок, пресет,
  ▶ = відмінне від заводського, відповідь камери, таймер);
- `commands.jsonl`, `журнал.txt` — команди й відповіді з часом від старту;
- `camera_before.json` / `camera_after.json` — стан камери до/після.

Відео пишеться 60-секундними шматками `.mkv` і в кінці склеюється в `.mp4`.
Якщо живлення зникло посеред польоту — шматки лишаються в теці, їх можна
відкрити як є. Наприкінці (або при перериванні) камера повертається до
початкових параметрів, `rotation 0`, `btn save`.

Назви палеток/сцен — з `1_MINI2instruction set.xlsx`. Пресети та сценарій —
`PRESETS` і `PLAN` на початку `flight_test.py`.
